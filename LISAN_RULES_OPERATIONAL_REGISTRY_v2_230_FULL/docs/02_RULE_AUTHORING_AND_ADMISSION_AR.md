# دليل صياغة وتصنيف وإدخال بنود «لسان القرآن» إلى سجل الحوكمة

**الحالة:** معيار تشغيلي **مقترح** لم يُعتمد بعد. يطبّق على البنود الجديدة والمراجعات ولا يعيد كتابة البنود التاريخية تلقائيًا.

## 1. فصل أربعة أسئلة مختلفة

| السؤال | الحقل | المعنى |
|---|---|---|
| ما طبيعة الحكم؟ | `kind` | مبدأ أو سياسة أو قيد أو ضابط أو متطلب أو تعليمة أو إرشاد |
| ما إلزام السلوك؟ | `force` | MUST / MUST_NOT / SHOULD / MAY داخل **نطاق** القاعدة |
| من أين تستمد سلطتها؟ | `authority_level` | أصل منهجي معتمد أو سياسة مشتقة أو عقد تنفيذ أو مسودة |
| هل هي نافذة حاليًا؟ | `rule_status` | PROPOSED / UNDER_REVIEW / APPROVED_INACTIVE / ACTIVE / SUSPENDED / SUPERSEDED / REJECTED |

لا تخلط `KIND` مع `FORCE`: قد يكون الضابط MUST أو SHOULD بحسب مصدره. ولا تعني كلمة «يجب» الواردة داخل مسودة أن البند ACTIVE؛ تُراجع السلطة والجهة المخولة والإصدار والقرارات.

## 2. قواعد صياغة بند فردي جيد

1. **ذري وواضح:** فعل أو التزام محدد قابل للتمييز. إذا احتوى النص شرطين قابلين للتغيير مستقلًا، اقترح فصل بندين مرتبطين. تجنّب حشر «التحقق + الموافقة + النشر + النسخ» في جملة واحدة.
2. **مخاطب محدد:** من ينفذه؟ الباحث، الوكيل، الخادم، صاحب القبول، Site، المدقق؟ لا تفترض أن «النظام» جهة كافية.
3. **شرط انطباق معلوم:** متى يسري؟ وضع الدراسة الداخلية، عند توليد دعوى، عند تعديل قاعدة، عند نشر بطاقة؟
4. **سلوك يمكن ملاحظته:** قل «يمنع خادم الأدلة الترقية إذا لم يُطابق المرجع» بدل «يحترم الأدلة» دون بيان محل الفعل.
5. **إلزام مضبوط:** MUST إلزام، MUST_NOT حظر، SHOULD توصية مع تبرير عدول، MAY خيار لا يمنح صلاحية بذاته.
6. **استثناءات لا تنقض الأعلى:** لا تضف «إلا عند الحاجة» دون جهة مخولة وشروط وحدود وتاريخ وسبب.
7. **لا مُفردات ادعاء غير قابلة للإثبات:** لا تقل «يعزل النموذج كليًا عن معرفة التدريب» أو «يضمن صحة المعنى»؛ قل ما يمكن فحصه في سياق وأدوات وإيصالات.
8. **لا تخلط الدليل بالثقة:** schema، hash، حساب أو اتفاق نماذج ليست براهين على صحة المعنى.
9. **اللغة الثنائية:** النصان العربي والإنجليزي يحفظان النفي والشرط والفاعل والهدف والزمن والإلزام والاستثناء والنطاق.
10. **لا رموز بيئات مؤقتة في نص القاعدة:** يسجل API أو إصدار Plugin أو اسم خادم في `implementation_mapping`؛ الجملة العامة مستقلة عن أسماء التطبيقات. الأسماء المنهجية المتفق عليها تُحفظ عند الحاجة.
11. **المصدر محفوظ بلفظه:** اقتباس المصدر، ونطاقه، وحالة الوثيقة، والقرار في حقول مستقلة؛ إعادة الصياغة ليست تعديلًا تلقائيًا لمصدر السلطة.
12. **لا تستبدل العمل البحثي بنتيجة اختبار:** كل قاعدة تختص بمعنى قرآني تحتاج مراجعة بشرية لمعقولية الاستدلال ولا تكتفي باختبار JSON.

## 3. قالب الصياغة الثنائية المفضل

`[Actor] + [MUST/MUST_NOT/SHOULD/MAY] + [Observable action] + [When/If condition] + [Scoped object] + [Failure treatment]`.

**إنجليزي:** *When a study requests official publication, the publication service MUST verify a valid review and approval for the exact locked revision and declared scope; otherwise it MUST withhold the official artifact.*

**عربي:** *عند طلب النشر الرسمي لدراسة، يجب أن تتحقق خدمة النشر من مراجعة واعتماد صالحين للنسخة المقفلة المحددة ونطاقها المعلن، وإلا تمنع إصدار البطاقة الرسمية.*

هذه صياغة إيضاحية قد تتقاطع مع قواعد موجودة؛ **لا تُضاف** بوصفها بندًا آخر إذا كان القديم يكفي، بل تُستخدم لتحسين قابلية الاختبار في عقده التشغيلي.

## 4. تصنيف KIND

- `PRINCIPLE` **مبدأ:** حقيقة منهجية تأسيسية أو علاقة سلطات، لا تعرّف وحدها واجهة API.
- `POLICY` **سياسة:** اختيار مؤسسي يحكم المسموح والممنوع أو انتقالات العمل.
- `CONSTRAINT` **قيد أو حظر:** يمنع فعلًا أو مصدرًا أو استنتاجًا محددًا.
- `CONTROL` **ضابط:** آلية للتأكد من سلامة فعل أو فرض حد تنفيذي.
- `REQUIREMENT` **متطلب:** خاصية لازمة في سجل أو واجهة أو خدمة.
- `INSTRUCTION` **تعليمة:** فعل إجرائي محدد للمشغّل أو الوكيل في مرحلة.
- `GUIDELINE` **إرشاد:** ممارسة مفضلة مرنة لا تُستعمل لإبطال سلطة أعلى.

**ملاحظة جودة:** قد يكون الحقل السابق `kind/force` غير متوافق مع الفعل اللغوي للبند. يُسجل اقتراح تعديل في `Classification Review`، ولا يُعدّل بلا مصالحة وإصدار.

## 5. معايير القبول — بوابات متتابعة

| البوابة | السؤال الحاسم | الدليل المطلوب | عند الفشل |
|---|---|---|---|
| AD-01 | هل النص المقترح مفهوم ومحدد؟ | نص EN/AR + مقابلة لفظية | RETURN_FOR_REWRITE |
| AD-02 | هل يتعلق بالمنهج أو المنتج بالفعل؟ | مجال + وحدة/مرحلة معنية | REJECT_OUT_OF_SCOPE |
| AD-03 | ما المصدر وحالته وسلطته؟ | Source ID + section + digest + status | QUARANTINE_SOURCE |
| AD-04 | هل يحمل إضافة دلالية غير مكررة؟ | closest_existing + relation + rationale | MERGE_OR_REFINE |
| AD-05 | هل يتعارض مع أعلى أو أحدث مقبول؟ | Authority map + conflicts | OWNER_DECISION_REQUIRED |
| AD-06 | هل KIND وFORCE متسقان؟ | مراجعة لغوية وتصنيفية | RETURN_FOR_CLASSIFICATION |
| AD-07 | هل شرط التفعيل دقيق؟ | Predicate ضمن عقد سياق محدد | HOLD_APPLICABILITY |
| AD-08 | هل المكلّف والصلاحية محددان؟ | owner/actor/role/route | HOLD_AUTHORIZATION |
| AD-09 | هل الإنفاذ المناسب موثق؟ | Code/config review أو HUMAN_REVIEW label | NO_ENFORCED_CLAIM |
| AD-10 | هل تصرف الفشل محدد؟ | Failure action + bounded retries | HOLD_IMPLEMENTATION |
| AD-11 | هل يوجد اختبار إيجابي؟ | Fixture + expected + actual + trace | NOT_RUN |
| AD-12 | هل يوجد اختبار سلبي؟ | Misuse fixture + outcome + trace | NOT_RUN |
| AD-13 | هل وُضعت خطة تأثير متوازنة؟ | Baseline+metrics+false-denial risk | IMPACT_NOT_MEASURED |
| AD-14 | هل الصياغة الثنائية متكافئة؟ | Blind bilingual review | RETURN_FOR_TRANSLATION |
| AD-15 | هل اعتمدتها جهة صحيحة وبنسخة ثابتة؟ | Actor receipt + digest + effective date | PROPOSED_ONLY |
| AD-16 | هل لا يزال التنفيذ ضمن الأدوات والإصدار الحقيقي؟ | Tested host/Plugin/LISAN contracts | DO_NOT_ACTIVATE |

ليس مطلوبًا إتمام جميع اختبارات الأثر الكمي قبل قبول **صياغة** مرشح غير نافذ؛ لكن إصدار **ACTIVE/VERIFIED_IN_SCOPE** يتطلب الأدلة ذات الصلة. المراجعة البشرية مطلوبة حيث الحكم دلالي لا حسابي. لا يُمنح PASS للخانة `NOT_RUN`.

## 6. مسار الإدخال والتغيير

`EXTRACTED_CANDIDATE → SOURCE_REVIEW → SEMANTIC_DEDUP → REWRITE → CLASSIFY → APPLICABILITY_REVIEW → AUTHORITY_CONFLICT_CHECK → IMPLEMENTATION_SPEC → TESTS → OWNER_APPROVAL → APPROVED_INACTIVE → ACTIVATION → MONITOR → REVALIDATE/REVISE/SUPERSEDE`.

**نتائج فحص العلاقة ببند قديم:** `IDENTICAL`, `SEMANTIC_DUPLICATE`, `REFINES_EXISTING`, `PARTIALLY_OVERLAPS`, `CONFLICTS`, `SUPERSEDES`, `INDEPENDENT_NEW`. تتطلب فئات الإحلال قرارًا محددًا يربط الإصدار الجديد بالقديم؛ لا تحذف الأصل التاريخي ولا تعيد ترقيم 190 بندًا.

**بوابة التغيير:** يمنع أي وكيل من منح نفسه مستوى `ACTIVE` أو رفع `authority_level` أو توقيع استثناء أو استبدال بند محمي. مساهمته اقتراح نص وتصنيف واختبار محتمل فقط.

## 7. فصل درجات النضج

| الحقل | مثال | ما يعنيه |
|---|---|---|
| `rule_status` | PROPOSED | صياغة موجودة ولا تُطبق تلقائيًا |
| `enforcement_status` | NOT_VERIFIED | لم يثبت ضابط عامل في النسخة المستهدفة |
| `review_status` | PENDING_INDEPENDENT_REVIEW | لم يُراجع عقد البند الخاص |
| `measurement_status` | NOT_MEASURED | ليس لدينا قياس أثر تجريبي |
| `implementation_status` | EXISTING_UNTESTED | توجد شيفرة أو تهيئة لكنها لم تختبر |
| `publication_status` | NOT_PUBLISHED | لا يملك سجل القاعدة سلطة نشر بحث قرآني |

## 8. برنامج مراجعة 190 بندًا دون إفقارها

لا تُعِد كتابة كل البندين اللغويين دفعة واحدة. نفّذ أولًا تدقيق تصنيف الحالات غير المنسجمة مع قوتها اللغوية (مثلاً النص الذي يتضمن MUST بينما `force=SHOULD`) ثم استكمل **عقد انطباق مفصل لكل بند** بديلًا عن `CATEGORY_BASED_INFERENCE`، ثم جرّب إنفاذه على بيانات مقيّدة قبل تشغيله. مصدر نصوص البنود 001–171 يحتاج تتبعًا أدق من المصدر المجمل في الجدول السابق؛ جرد النصوص الأصلي مشروع مستقل لإثبات السلطة، ولا تدّع إنهاءه.
