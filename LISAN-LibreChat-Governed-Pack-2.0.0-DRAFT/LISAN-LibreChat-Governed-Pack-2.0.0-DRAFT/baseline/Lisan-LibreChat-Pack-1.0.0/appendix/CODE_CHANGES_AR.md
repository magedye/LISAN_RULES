# ملحق التطوير اللازم لأعلى درجة التزام

لا يحتوي هذا الملحق على تغييرات منفذة. البداية الموصى بها هي إعادة استخدام خدمة لسان القائمة وتوسيع مواضع النقص المثبتة، مع بقاء LibreChat واجهة. لا يُبرَّر Fork للمنصة إلا إذا تعذر فرض العقد من API/adapter أو إعداد مدعوم، وثبت ذلك باختبار.

## C01 — إنفاذ حدود السياق وBlind Lab

المشكلة: تعطيل Memory والأدوات واستخدام محادثة جديدة يقلل التعرض، لكنه لا ينتج برهانًا خادميًا على كل ما دخل السياق. التدقيق النصي لا يستطيع منع prompt ملوث أو معرفة التدريب.

المقترح: منظم سياق على الخادم يختار ملف البحث من سياسة موثوقة، ويكوّن قائمة مصادر وأدوات مسموحة قبل استدعاء النموذج. في INDEPENDENT يُرفض تحميل دراسات سابقة أو Project files أو Memory أو نتائج مسار خارجي، وتُفحص مدخلات التفويض. يسجل manifest للمحتوى الفعلي والهوية والبصمات؛ محتواه ليس قرارًا بأن الدلالة صحيحة. لا يمنع الباحث من البحث العام؛ إذا تعذر العزل تُصحح تسمية المسار.

معيار القبول: محاولة حقن مصدر خارجي عبر الرسالة والملف والمهارة والتفويض والاستئناف تفشل في إدخاله كمصدر في الملف المعزول؛ يُختبر مسار إيجابي للشواهد المسموحة. لا ادعاء بمحو معرفة التدريب حتى بعد نجاحه. الأولوية عالية عند طلب ضمان عزل ملزم.

## C02 — ربط التنفيذ بالأدلة والإيصالات الدائمة

المشكلة: stdio الحالي يحمل إيصالات مؤقتة مرتبطة بعملية/هوية محلية؛ تعدد العمليات وإعادة التشغيل قد يقطع قابلية التحقق. سجل محادثة قابل للتصدير ليس سجل أدلة غير قابل للتبديل.

المقترح: خدمة أدلة بهوية جلسة خادمية ومفاتيح تدوير وصلاحية واضحة، تربط run_id وactor وcorpus/method hashes والاستعلام والمراجع والاستجابة وإصدار النتيجة. تتحقق من الأدلة عند الاستعمال، وتحفظ ملخصًا علنيًا للاستدلال دون التفكير الخفي. تبقى أدوات النموذج غير قادرة على توليد إيصال أو تغيير هوية الفاعل.

معيار القبول: رفض إيصال مزور/من مستخدم آخر/من مصدر مختلف/منتهي، وإعادة استرجاع سليمة بعد إعادة التشغيل، ونقل مشروع للأدلة بين وكلاء مأذونين دون مشاركة سر التوقيع. الفشل يمنع الدعوى المتأثرة، لا يعاد وصفه نجاحًا شكليًا.

## C03 — سجل دراسات دائم واسترجاع مؤهل

المشكلة: لا توجد في الحزمة السباعية عمليات حفظ. ملف يدوي يمكن أن ينسخ أو يعدل، وMemory/RAG لا يفرضان قبولًا أو نسخه أو مصدرًا.

المقترح: افحص أولًا خدمة التراكم الموجودة في حزمة 14 أكتوبر. عند كفايتها أعد استخدامها بعقودها الأصلية `quran-lisan-study/1` و`lisan-repository-document/1`، مع مصادقة مستقلة عن arguments النموذج، expected_revision وidempotency_key ومعاملات وتسجيل تاريخ النسخ. لا تنشئ محرك حالات موازٍ. أضف واجهة مراجعة بشرية لها نطاق قرار معلوم؛ لا أداة model تمنح semantic acceptance. الفصل بين research_state وcanonical_state لا يُستورد إلا عند وصل محرك canonical الرسمي بعقده.

لكل دراسة احفظ الشواهد والفرضيات المرفوضة وغير المحسومة والتغطية وقوة كل دعوى والمراجعة والإصدار والتبعيات. يسترجع INDEPENDENT بيانات منهجية فقط بلا نتائج سابقة؛ CUMULATIVE_COMPARISON يسترجع ما تجيزه سياسة الخدمة مع سجل تعرض، ويعيد فحص الشواهد. fixture وTEST_MOCK وunverified-source لا تدخل معرفة canonical. نتائج البشر ليست أدلة قرآنية أولية.

معيار القبول: فصل مستخدمين، منع تغيير actor من النموذج، رفض تعارض revision دون overwrite، idempotency حقيقي، استبعاد نتيجة معاد فتحها من القراءة المؤهلة، نسخ/استعادة مثبتة، فحص المصدر، وعدم ارتفاع حالة الدراسة لأن فحصًا ميكانيكيًا نجح. الأولوية عالية عند تحويل الحفظ من يدوي إلى آلي.

## C04 — التبعيات وإعادة الفحص

المقترح: ربط كل claim بإصدار الشاهد والاستعلام والمنهج والنتائج التي أثرت فيه. تغير المصدر أو سحب مراجعة يحدد المتأثر ويفتحه لإعادة الفحص وفق العقد القائم، ويمنع ظهور النسخة القديمة كأنها الجارية المؤهلة. لا يستعمل النموذج حقلًا مولدًا ذاتيًا ليعفي النتيجة من المراجعة.

معيار القبول: مثال بنتيجة تعتمد على نتيجة أخرى؛ تعديل الأصل يُظهر أثره ويمنع توريث الثقة القديمة، مع حفظ التاريخ. النتائج غير المتأثرة لا تعاد مراجعتها بلا سبب. Graph للعرض مشتق من السجل، وليس أصل المعرفة.

## C05 — مراجعة مستقلة قابلة للإسناد

المقترح: تثبيت candidate hash، وهوية المراجع، وسجل المشاركة السابقة والتعرض، وحدود المواد المقدمة، ومعايير المراجعة. لا يراجع المنشئ عمله ثم يختار INDEPENDENT. يسمح النظام بمراجعة داخلية مفيدة تحمل تسميتها، وباعتراضات لم تحسم. قبول الإصدار لصاحب السلطة المخولة، ولا يقرر المعنى Steward إداري.

معيار القبول: محاولة نفس المنشئ منح الاستقلال ترفض، وأي تغيير مؤثر في النسخة يفسد ربط المراجعة القديمة بها. تغيير النموذج وحده لا يفي بالشرط. لا قفل Purity/Lock إداري على حق البحث؛ الشروط تخص تأهيل النتيجة أو canonicalization في موضعها الرسمي.

## C06 — تقييم النماذج ومعايرة الثقة

المقترح: مجموعة عربية محددة المصدر، أسئلة واستعلامات ومراجع محكَّمة، وسيناريوهات عمياء بمصادر فرضيات مخفية عن المقيم قدر الإمكان. قياس الاسترجاع والاقتباس والعد منفصل عن دعم الدلالة. إذا أريد احتمال ثقة رقمي فليُعرَّف الهدف وتجمع بيانات معايرة مستقلة واختبارات خارج العينة؛ لا مجموع أوزان انتقائي أو تقييم ذاتي.

معيار القبول: إعادة إنتاج الفحوص على نسخة نموذج/إعدادات معلومة، وعرض فشل المعايرة حيث يقع. خلاف المراجعين يُحفظ ولا يحوَّل آليًا إلى حقيقة بتصويت. الأولوية متوسطة بعد التشغيل الأساسي، وضرورية قبل نشر نسب ثقة ذات معنى.

## C07 — واجهة البطاقات والمراجعة المنظمة

المقترح: صفحة بحث تعرض النص الأصلي والمواضع والتغطية وطبقات المساهمة والبدائل والفحوص والإصدار، وتمنع إخفاء UNKNOWN أو PARTIAL بالتنسيق. يمكن تقديمها MCP App/خدمة مجال مناسبة قبل تعديل قلب LibreChat. لا يكفي Artifact مولد ليكون شاشة قرار موثوقة.

معيار القبول: اتساق البطاقة مع السجل بعد التعديل وإعادة الفتح، وتمييز درجات الدليل والعد عن درجات الثقة. إخراج بصري أفضل لا يرفع حالة النتيجة. الأولوية حسب استعمال الباحثين بعد اكتمال عقود السجل.

## ما لا يحتاج برمجة جديدة الآن

Instructions، وSkills، وMCP stdio المحلي، وتوزيع الأطفال، وتعطيل الذاكرة والمصادر الزائدة، والمكتبة والمشاريع، والتصدير والمراجعة اليدوية. يمكن إجراء بحث ذي قيمة بهذه الحدود. لا يُنسب إليه إنفاذ أو قبول لم يُبن أو يُختبر.


## C08 — مخرجات مرحلية محكومة وتقييم انجراف التعليمات

حيث يثبت الاحتياج، ينفذ adapter على المضيف تحققًا من schema الأصلي وأنواع claims وروابط الأدلة، مع فصل observation عن inference ومنع عرض نجاح مرحلة لم تنفذ. Structured Outputs يعتمد دعم النموذج/المزود فعليًا، وليس مفتاح YAML عامًّا نفترضه لكل مزود. إذا فشل المخطط تُعاد محاولة محدودة بخطأ محدد؛ لا يخترع النظام شواهد لملء الحقول. بعد استنفاد الحد تحفظ الحالة الجزئية وحدودها. المراحل المطلوبة تتناسب مع الادعاء الجديد؛ لا نفرض إعادة الدحض الكامل لإجابة تنقل نتيجة مراجعة ضمن نطاقها.

القواعد الحرجة تبقى في Instructions؛ اختيار المهارة أو تحميلها أو وجودها على القرص لا يثبت تنفيذها. يسجل المضيف ما يستطيع رصده فعلًا وبصمات التعليمات والمهارات والمدخلات. عند غياب signal صريح يصرح بعدم قابلية الملاحظة بدل اختلاقه. اختبار تغير الصياغة والنموذج والسياق يقيس السلوك الظاهر، لا يثبت فهمًا باطنيًا. قواعد المصدر وحدود السلطة لا تتغير بتغيير اللغة أو شكل الإخراج.

معيار القبول: رفض بنية غير صالحة وروابط أدلة مختلقة وقلب فرضية إلى ملاحظة، مع حالة نجاح صحيحة؛ توقف التصحيح بعد حده؛ توثيق تغير التعليمات؛ عدم خلط سجل نية النموذج بأثر تنفيذ الأداة أو قرار اعتماد. يبقى الحكم في صحة وجه الاستدلال مهمة مراجعة تتجاوز JSON Schema. هذا توسيع محتمل لـC01/C02 وC06، وليس تبني إطار AGHR كاملًا أو تشريع حالات جديدة للسجل.
