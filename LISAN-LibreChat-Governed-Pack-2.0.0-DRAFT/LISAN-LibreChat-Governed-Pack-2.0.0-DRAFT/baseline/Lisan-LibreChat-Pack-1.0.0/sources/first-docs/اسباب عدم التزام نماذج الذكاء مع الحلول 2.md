لا يوجد “عصيان” واعٍ من النموذج؛ بل تعارض بين تعليماتك وبين ما تعلّمه النموذج إحصائيًا، مع حدود في الانتباه والسياق وغياب ضمانات تنفيذ حتمية. لذلك، الصياغة الأفضل تحسّن الالتزام كثيرًا، لكنها لا تضمنه بنسبة 100%؛ الحل العملي هو هندسة التوجيه + ضوابط برمجية تتحقق من المخرجات. [direct.mit](https://direct.mit.edu/coli/article/50/3/1053/121669/Large-Language-Model-Instruction-Following-A)

## المعالجات على مستوى الـ Prompt

- ضع القاعدة الحرجة في **أعلى الـ prompt**، ثم أعد تذكيرها في **النهاية قبل التوليد**؛ هذا يقلّل تأثير “تلاشي الانتباه”. [linkedin](https://www.linkedin.com/pulse/smart-intern-problem-why-your-ai-ignores-instructions-qpxrc)
- استخدم تعليمات إيجابية وقابلة للتنفيذ: بدل “لا تكتب شرحًا” اكتب: `أخرج JSON فقط. لا تضف أي نص قبل أو بعد الكائن.`
- حدّد المخرج بمخطط صريح: أسماء الحقول، أنواعها، القيم المسموحة، وما يجب فعله عند نقص البيانات مثل `"unknown"`.
- افصل الأقسام بوضوح: `الدور`، `القواعد الإلزامية`، `السياق`، `المهمة`، `تنسيق المخرج`، `أمثلة`.
- أضف أمثلة Few-shot مطابقة تمامًا للمخرج المطلوب، خصوصًا في التحويل، التصنيف، والاستخراج.
- اطلب من النموذج أن يفكر داخليًا أو يشرح باختصار قبل الإجابة عند المهام المعقدة، ثم ينتج المخرج النهائي وفق القالب.
- قلّل العشوائية للمهام الحساسة: ابدأ بـ `temperature=0` أو `0.1`، واضبط `top_p` بحذر. [linkedin](https://www.linkedin.com/pulse/smart-intern-problem-why-your-ai-ignores-instructions-qpxrc)
- لا تضع أكثر من قيد حرج واحد في جملة واحدة؛ وزّعها في قائمة مرقمة.
- عند تعارض محتمل، اكتب أولوية واضحة:
  `إذا تعارضت القواعد، الأولوية لقواعد المخرجات، ثم للأمان، ثم للأسلوب.`

### قالب عملي

```text
أنت مساعد دقيق للمهام التقنية.

القواعد الإلزامية:
1. أخرج JSON صالحًا فقط.
2. لا تكتب أي مقدمة أو شرح أو علامات Markdown.
3. استخدم الحقول التالية فقط: title, risk, recommendation.
4. إن لم تتوفر معلومة، ضع القيمة "unknown".
5. لا تخترع حقائق أو أرقامًا.

السياق:
{النص أو البيانات}

المهمة:
حلّل النص واستخرج المخاطر والتوصيات.

تنسيق المخرج:
{
  "items": [
    {
      "title": "string",
      "risk": "low | medium | high",
      "recommendation": "string"
    }
  ]
}

تذكير نهائي:
أخرج JSON فقط، بدون أي نص إضافي.
```

## المعالجات الهندسية الأقوى

القاعدة الذهبية: **لا تجعل النموذج “يعد” بالتزام؛ اجعل النظام يتحقق من الالتزام.** [dev](https://dev.to/jsvnsk-tech/why-ais-seemingly-misbehave-1410)

- **Structured Outputs / JSON Schema:** استخدم `response_format` أو JSON Schema أو Function/Tool Calling لإجبار بنية المخرج على مستوى الـ API، لا على مستوى النص فقط. [linkedin](https://www.linkedin.com/pulse/smart-intern-problem-why-your-ai-ignores-instructions-qpxrc)
- **Validator بعد التوليد:** تحقق برمجيًا من JSON، الحقول، الأنواع، القيم المسموحة، الطول، اللغة، وعدم وجود نص زائد.
- **Retry مع تصحيح:** إذا فشل التحقق، أعد الطلب مع رسالة خطأ محددة:
  `المخرج السابق غير صالح لأن الحقل risk يجب أن يكون low/medium/high. أعد الإنتاج فقط كـ JSON.`
- **استخرج المهمة الحساسة إلى كود:** الحسابات، التواريخ، IDs، الصلاحيات، وعمليات قاعدة البيانات يجب أن ينفذها كود حتمي أو أداة، وليس النموذج.
- **RAG مع مصادر موثوقة:** عند الحاجة إلى معلومات دقيقة، اجلب المصدر برمجيًا ومرّر النص ذا الصلة للنموذج؛ لا تعتمد على ذاكرته.
- **قصر نطاق الوكيل:** في أنظمة الـ Agents، حدّد الأدوات المتاحة، الصلاحيات، حد الخطوات، والموافقة البشرية قبل الإجراءات الخطرة.
- **Guardrails:** طبقة منفصلة تفحص السياسات، المحتوى، الأدوات المستدعاة، والمعاملات قبل التنفيذ.
- **اختبارات انحدار للـ Prompts:** أنشئ مجموعة حالات اختبار، وقِس نسبة الالتزام بالتنسيق والقواعد بعد كل تغيير في النموذج أو التعليمات.
- **Human-in-the-loop:** للقرارات عالية الأثر، اجعل النموذج يقترح فقط، والإنسان أو النظام يوافق وينفذ.

## الخلاصة العملية

2. اجعل المخرج structured عبر Schema أو Tool Calling.
