# تحليل: لماذا يتسرب الموروث رغم التعليمات — وكيف نُترجم LISAN إلى إنفاذ معماري في LibreChat

التشخيص أولاً: المشكلة ليست في صياغة الـ prompt. الـ prompt الذي أرسلته منضبط منهجياً بدرجة عالية، ويحتوي على 35 مادة تغطي معظم ما تحتاجه LISAN. لكن **التسرب إلى الموروث لا يُعالج بالتعليمات**، لأنه لا يأتي من قراءة المفسرين، بل من **أوزان النموذج نفسها**. سأشرح الآلية بدقة، ثم أقدم الترجمة المعمارية التي تُنفّذ LISAN في LibreChat بحيث يصبح التسرب قابلاً للكشف والمنع، لا مجرد نهي لفظي.

---

## أولاً: تشخيص آلية التسرب — سبعة مصادر لا يحلها النهي

| المصدر | كيف يتسرب | لماذا لا ينفع النهي |
| :--- | :--- | :--- |
| **1. تلوث الأوزان** | كلمة مثل "صلوات" تُستدعى من التوزيع الاحتمالي مع معانيها التراثية | التعليمات لا تمحو الأوزان؛ النموذج "يعرف" المعنى قبل أن يقرأ الشواهد |
| **2. Anchoring** | بعد أن يرى النموذج المفردة، تُثبَّت فرضية أولية من المعنى المألوف، ثم تُفسَّر الشواهد على أساسها | النموذج لا يعترف بأنه بدأ من فرضية مسبقة؛ يقدّمها كأنها ملاحظة |
| **3. الاستدلال الضمني** | النموذج لا يحتاج إلى الاستشهاد بمعجم؛ يستخدم الموروث كحدس لغوي | لا يمكن كشفه من النص المُنتَج، لأنه لا يذكر مصدره |
| **4. تراجع الصلاحية** | في prompt طويل، تعليمات الحظر في الأعلى تصبح أقل حضوراً عند مرحلة التحليل | الانتباه يتوزع، والحظر يضعف |
| **5. تحيّز التأكيد** | النموذج يولّد فرضية توافق الموروث، ثم يجد شواهد مؤيدة، ويتجاهل المضادة | النموذج "يبحث" لكنه يبحث في اتجاه واحد |
| **6. ملء الفراغ** | عند غياب corpus فعلي، يملأ النموذج الفراغ بمعرفته السابقة | الـ prompt لا يمنع هذا إذا لم يوفر corpus حقيقياً |
| **7. ضغط السياق** | إذا طُلب تحليل عميق، يضغط النموذج مراحل ويقفز من الملاحظة إلى النتيجة | التعليمات لا تُلزم ببوابات إجرائية |

**الخلاصة التشخيصية:** الـ prompt الجيد يُقلل التسرب لكنه لا يمنعه، لأن التسرب يحدث **داخل النموذج**، لا في النص. الحل هو **الإنفاذ الخارجي**: بنية إجرائية تمنع النموذج من الوصول إلى النتيجة قبل أن يمر بالمراحل، وتوفر له corpus حقيقياً يقرأه بدلاً من أن يتذكره، وتكشف المخرجات التي تحمل بصمة الموروث.

## ثانياً: المبدأ المعماري — "الإنفاذ لا التوجيه"

بدل أن نقول للنموذج "لا تستخدم الموروث"، نبني منظومة بحيث:

1. **لا يستطيع الوصول إلى الموروث** في مرحلة الاكتشاف (لا أدوات، لا إنترنت، لا معاجم).
2. **لا يستطيع تجاوز المراحل** (بوابات إجبارية بين كل مرحلة).
3. **لا يستطيع ملء الفراغ** من ذاكرته (corpus حقيقي يُحقن في السياق).
4. **لا يستطيع إخفاء التلوث** (مخطط إخراج يُلزمه بتصنيف كل ادعاء).
5. **لا يستطيع تجميل النتيجة التراثية** (كاشف تلوث مستقل).

هذا هو الفرق بين "منهجية مكتوبة" و"منهجية مُنفَّذة". الـ prompt الحالي منهجية مكتوبة ممتازة؛ ما نبنيه في LibreChat هو **المنهجية المُنفَّذة**.

## ثالثاً: الترجمة إلى LibreChat — تصميم تنفيذي من سبع طبقات إنفاذ

### الطبقة 1: Blind Lab كبيئة معزولة فعلياً (لا مجرد Subagent)

**المشكلة:** Subagent في LibreChat يرث سياق المستخدم وربما أدواته، ويستطيع النموذج فيه استدعاء معرفته التدريبية.

**الحل:** Blind Lab يُدار عبر **MCP server** يتحكم في ما يُحقن في سياق الوكيل:

- الوكيل لا يملك أدوات بحث ويب، ولا معاجم، ولا تفسير.
- الوكيل يملك فقط أدوات corpus: `quran.search`, `quran.get_occurrences`, `quran.get_verse`, `quran.get_morphology`.
- كل استدعاء يمر عبر MCP يتحقق من أن الطلب داخل نطاق Blind Lab، ويُسجّل في run log.
- **لا يُحقن** في سياق الوكيل أي ملخص سابق، ولا عنوان ملف، ولا نتيجة محادثة أخرى.
- **يُحقن** فقط: السؤال، نطاق البحث، وبيانات corpus التي يطلبها.

**في LibreChat:**

```yaml
mcpServers:
  lisan-corpus:
    type: "stdio"
    command: "python"
    args: ["-m", "lisan_corpus_mcp"]
    # أدوات: search, occurrences, morphology, verse, parallel, contrast
  lisan-registry:
    type: "stdio"
    command: "python"
    args: ["-m", "lisan_registry_mcp"]
    # أدوات: save_finding, get_finding, lock_result, request_review
```

Blind Lab agent:

```
tools: [lisan-corpus.*]   # فقط
blocked: [web_search, file_search, memory_global, tafsir_*, dictionary_*]
```

### الطبقة 2: بوابات المراحل الإجبارية (Agent Chain + Skills)

المنهجية في الـ prompt تصف تسلسلاً: `LEXICAL BLIND PASS → CORPUS OBSERVATIONS → SEMANTIC HYPOTHESES → COUNTEREVIDENCE → FALSIFICATION → SUPPORTED RESULT → VERSE CONTEXTUALIZATION`.

**المشكلة:** النموذج يستطيع "القفز" من الملاحظة إلى النتيجة، أو تقديم الفرضية كأنها ملاحظة.

**الحل:** تقسيم التسلسل إلى **وكلاء متسلسلين** في Agent Chain، بحيث:

- كل وكيل يستقبل فقط **مخرج المرحلة السابقة** (مخطط بمخطط).
- لا يبدأ الوكيل التالي قبل أن يُنتج السابق **مخرجاً مطابقاً للمخطط**.
- كل مخرج يحمل **حالة معرفية** (`OBSERVATION` / `HYPOTHESIS` / `TESTED` / `SUPPORTED` / `UNRESOLVED` / `REJECTED`).

| الوكيل/المهارة | المدخل | المخرج الإلزامي | البوابة |
| :--- | :--- | :--- | :--- |
| `blind-lexical-pass` | المفردة فقط (لا آية، لا سياق) | وصف شكلي: اللفظ، الصيغة، الجذر إن تحقق | لا يمر إلا إذا لم يذكر أي معنى |
| `corpus-observation` | استدعاء `lisan-corpus.search` | جدول ملاحظات: موضع، فاعل، مفعول، متعلق، مقابلة، نفي/إثبات | لا يمر إلا إذا كانت كل ملاحظة قابلة للتحقق من النص |
| `hypothesis-builder` | جدول الملاحظات فقط | فرضية محددة + تنبؤات + شرط رفض | لا يمر إلا إذا كانت الفرضية قابلة للنقض |
| `counterevidence-hunter` | الفرضية + corpus | قائمة بأصعب المواضع + تصنيف SUPPORTING/COUNTEREVIDENCE/AMBIGUOUS | لا يمر إلا إذا ذكر موضعاً واحداً على الأقل يضغط الفرضية |
| `falsification-tester` | الفرضية + المضاد | نتيجة الاختبار: نجت / عُدّلت / ضُيّقت / رُفضت | لا يمر إلا إذا نفّذ اختباراً حقيقياً |
| `internal-result-locker` | مخرجات كل ما سبق | `INTERNAL_SEMANTIC_RESULT` + الحالة | **يقفل** النتيجة ويولّد hash |
| `contextualizer` | النتيجة المقفلة + الآية | المعنى الموضعي مع فصل النواة عن السمات والسياق | لا يمر إلا إذا احترم القفل |
| `external-comparator` | النتيجة المقفلة + طلب المستخدم | `POST_LOCK_EXTERNAL_COMPARISON` | لا يبدأ إلا بعد القفل، ويُظهر ما يوافق وما يخالف |

**المفتاح:** كل وكيل يعمل في **سياق جديد** لا يحمل تاريخ المرحلة السابقة إلا كمخرج منظم. هذا يمنع "تراجع الصلاحية" ويمنع تحويل الفرضية إلى ملاحظة.

### الطبقة 3: حقن corpus حقيقي بدل الاسترجاع من الذاكرة

**المشكلة:** الـ prompt يقول "اجمع الشواهد" لكنه لا يوفر corpus، فيملأ النموذج الفراغ من ذاكرته.

**الحل:** أدوات MCP تُرجع corpus فعلياً:

```python
# lisan-corpus MCP tools
quran.search_root(root: str) -> list[Occurrence]      # كل مواضع الجذر
quran.search_lemma(lemma: str) -> list[Occurrence]
quran.search_form(form: str) -> list[Occurrence]
quran.get_occurrence(ref: str) -> Occurrence           # سورة:آية + كلمة
quran.get_morphology(ref: str) -> Morphology           # صيغة، إعراب
quran.get_verse(ref: str) -> Verse                     # الآية كاملة
quran.get_parallel(ref: str) -> list[Verse]            # مواضع مشابهة بنيوياً
quran.get_contrast(ref: str) -> list[Contrast]         # مقابلات داخلية
quran.count_occurrences(root: str) -> int              # عدد حتمي
quran.coverage_report(scope: Scope) -> Coverage        # بسط/مقام
```

**لماذا هذا حرج:** عندما يقرأ النموذج 47 موضعاً فعلياً لجذر ما، ويحصل على الفاعل والمفعول والمتعلقات لكل موضع، يصبح لديه **دليل قابل للتحقق** بدل أن يستدعي من ذاكرته. الملاحظة تصبح مبنية على بيانات، لا على تذكر.

### الطبقة 4: مخططات إخراج تُلزم بتصنيف الادعاءات (Structured Output)

**المشكلة:** النموذج يخلط بين الملاحظة والفرضية والاستنباط في فقرة واحدة.

**الحل:** كل مخرج من كل وكيل يجب أن يطابق مخطط JSON صارم:

```json
{
  "phase": "corpus_observation",
  "word": "صلوات",
  "root_verified": true,
  "root": "ص-ل-و",
  "coverage": {"total_occurrences": 47, "examined": 47, "status": "FULL"},
  "observations": [
    {
      "ref": "2:157",
      "form": "صَلَوَاتٌ",
      "subject": "الله",
      "preposition": "على",
      "object": "النبي",
      "contrast": null,
      "negation": false,
      "note": "تأتي مع فاعل الله ومتعلق 'على'"
    }
  ],
  "heritage_markers": [],   // أي إشارة إلى معرفة تراثية غير مستندة إلى corpus
  "unverified_claims": []
}
```

الوكيل التالي لا يقبل مخرجاً لا يطابق المخطط. هذا يمنع "القفز" ويمنع "التجميل".

### الطبقة 5: كاشف التلوث بالموروث (Heritage Contamination Auditor)

**المشكلة:** النموذج قد ينتج نتيجة تبدو منهجية لكنها في الحقيقة تراثية، دون أن يذكر مصدراً.

**الحل:** وكيل مستقل (أو Skill) وظيفته الوحيدة **كشف بصمة الموروث** في المخرجات. يعمل بمعايير مثل:

| المؤشر | كيف يُكشف | الإجراء |
| :--- | :--- | :--- |
| **تطابق مع تفسير مشهور دون دليل corpus** | مقارنة النتيجة بمصادر تراثية (خارج القفل، بغرض الفحص فقط) | وسم `POSSIBLE_HERITAGE_MATCH` |
| **فرضية تفسر كل شيء بلا استثناءات** | فحص `counterevidence` — إذا كان فارغاً أو ضعيفاً | وسم `SUSPICIOUS_UNIFORMITY` |
| **قفزة من ملاحظة إلى نتيجة** | فحص تسلسل المخرجات: هل توجد مرحلة وسيطة مفقودة؟ | رفض المخرج |
| **لغة توحي باليقين دون دليل** | فحص لغوي: "المعنى الحقيقي"، "قطعاً"، إلخ | رفض أو إعادة صياغة |
| **معنى لا يظهر في corpus لكنه في النتيجة** | مقارنة النتيجة بالمواضع المسترجعة | وسم `UNGROUNDED` |
| **إغفال موضع مضاد معروف** | فحص corpus نفسه عن مواضع كان يجب ذكرها | وسم `SELECTIVE_EVIDENCE` |
| **إعادة صياغة معجمية** | مقارنة النواة المقترحة بمداخل معجمية (بعد القفل فقط) | وسم `DICTIONARY_ECHO` |

هذا الكاشف لا يحكم بالصحة، بل **يُعلّم** المخرج للمراجع البشري أو للمرحلة التالية. وهو نفسه يعمل بأدوات حتمية (مقارنة نصوص، فحص تسلسل، إحصاء) لا بتقدير لغوي.

### الطبقة 6: آلية القفل (Lock Mechanism)

**المشكلة:** النموذج يستطيع الرجوع إلى الموروث "في الخلفية" ثم تقديم النتيجة كأنها من corpus.

**الحل:** النتيجة الداخلية تُقفل رقمياً قبل أي وصول خارجي:

1. `internal-result-locker` يُنتج `INTERNAL_SEMANTIC_RESULT` مع hash.
2. `lisan-registry.save_finding` يحفظه بحالته (`HYPOTHESIS` / `SUPPORTED` / `UNRESOLVED` / `REJECTED`) وإصداره.
3. **بعد القفل فقط** يمكن تشغيل `external-comparator` الذي يملك أدوات الوصول إلى المعاجم والتفاسير.
4. أي تعديل على النتيجة بعد المقارنة الخارجية يُنتج **إصداراً جديداً**، ولا يُعدّل الإصدار المقفل.

هذا يمنع الدورة: `معجم → فرضية → شواهد → نتيجة`، ويُجبر الدورة الصحيحة: `شواهد → فرضية → نقد → نتيجة مقفلة → مقارنة خارجية`.

### الطبقة 7: فصل النماذج وتنويعها

**المشكلة:** إذا استخدمنا نفس النموذج في كل المراحل، فتحيّزاته تنتقل من مرحلة إلى أخرى.

**الحل:** توزيع النماذج بحسب المرحلة:

| المرحلة | النموذج المقترح | لماذا |
| :--- | :--- | :--- |
| `blind-lexical-pass` | نموذج منخفض الحرارة، صارم في اتباع المخططات | يقلل الانحراف |
| `corpus-observation` | نموذج قوي في القراءة البنيوية | يقرأ الجداول بدقة |
| `hypothesis-builder` | نموذج قوي في الاستدلال، حرارة أعلى قليلاً | يسمح بالإبداع المنضبط |
| `counterevidence-hunter` | نموذج مختلف عن الذي ولّد الفرضية | يقلل تحيّز التأكيد |
| `falsification-tester` | نموذج منخفض الحرارة + أدوات حتمية | يمنع التجميل |
| `heritage-auditor` | نموذج مختلف + أدوات مقارنة | يكشف التلوث |
| `contextualizer` | نموذج قوي في التركيب | يركب المعنى |

هذا التنويع ليس كماليات؛ هو **إجراء منهجي** لتقليل التلوث المشترك بين المراحل.

## رابعاً: الأدوات الحتمية المطلوبة (لا تُترك للنموذج)

هذه الأدوات هي العمود الفقري لمنع التسرب، لأنها تُرجع **بيانات** لا **تقديرات**:

| الأداة | الوظيفة | لماذا حتمية |
| :--- | :--- | :--- |
| `quran.count_occurrences` | عدد المواضع | النموذج لا يعدّ بدقة |
| `quran.coverage_report` | بسط/مقام التغطية | النسبة تُحسب برمجياً |

| `quran.get_morphology` | الصيغة والإعراب | النموذج يخطئ في الصرف |
| `quran.get_parallel` | المواضع المتوازية بنيوياً | النموذج يفوّت |
| `quran.get_contrast` | المقابلات الداخلية | النموذج يغفل |
| `lisan.lock_result` | قفل النتيجة بـ hash | يمنع التعديل الرجعي |
| `lisan.get_finding` | استرجاع نتيجة بإصدارها | يمنع الخلط بين الإصدارات |
| `lisan.detect_heritage_markers` | فحص آلي لبصمات تراثية | يكشف التلوث |
| `lisan.compute_falsification_result` | نتيجة اختبار الدحض | لا تُترك للنموذج |

## سادساً: حدود ما يمكن ضمانه (أمانة منهجية)

يجب أن نكون صريحين:

1. **لا يمكن منع التلوث الداخلي بنسبة 100%**، لأن أوزان النموذج تحتوي الموروث. يمكن كشفه وتقليله ووسمه، لا محوه.
2. **يمكن منع التلوث القابل للكشف**: قفزة المراحل، الإغفال المتعمد، اللغة القاطعة، الادعاء غير المستند إلى corpus.
3. **جودة الـ corpus تحدد سقف الجودة**: إذا كان corpus ناقصاً، فالتغطية جزئية ويجب أن تُعلن كذلك.
4. **الأدوات الحتمية ضرورة لا رفاهية**: بدونها، العد والتحقق والتغطية تبقى تقديرات.
5. **المراجع البشري يبقى ضرورياً**: كاشف التلوث يُعلّم، لا يحكم. القرار النهائي بالاعتماد يبقى لصاحب الصلاحية.

### المرحلة 2: بناء الوكلاء السبعة (لا 37)

3. `Hypothesis Builder` — ملاحظات فقط.

8. `Contextualizer` — النتيجة المقفلة + الآية.

### المرحلة 5: اختبارات كشف الفشل

- محاولة تعديل نتيجة مقفلة، ومراقبة هل يُنتج إصدار جديد أم يُعدّل القديم.

## الخلاصة

الـ prompt الذي أرسلته **منهجية مكتوبة ممتازة**، ويحقق نسبة كبيرة من المطلوب. لكن التجاوز الذي تشكو منه — التمسك بالموروث رغم النهي — **لا يُحل بتحسين الـ prompt**، لأن مصدره أوزان النموذج لا نص التعليمات. الحل هو ما تقدمه LibreChat: **فصل الوكلاء، بوابات المراحل، حقن corpus حقيقي، مخططات إخراج، كاشف تلوث، وقفل النتيجة قبل المقارنة الخارجية**.

بهذا التصميم، يبقى الـ prompt هو "الدستور"، لكن الإنفاذ يصبح **معمارياً**: النموذج لا يستطيع الوصول إلى الموروث في مرحلة الاكتشاف، ولا يستطيع تجاوز المراحل، ولا يستطيع إخفاء التلوث. النتيجة: منهجية LISAN تصبح **مُنفَّذة** لا **مُوصى بها**، والتسرب يصبح **قابلاً للكشف والوسم**، لا مجرد نهي لفظي.
