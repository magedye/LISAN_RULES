# IPP — معالجة المدخلات وتوجيه البحث
نسخة تطبيق المرشح للملحق IPP1.1؛ ليست منظومة Orchestrator ثانية أو سياسة أعلى.

| المسار | مدخل التنفيذ | ما لا يدعيه |
|---|---|---|
| METHOD | question وmode:METHOD، أو قراءة المرجع فقط | لا يحتاج المتن ولا يختلق أداة |
| LOCAL_CONTEXT | refs وcontext0..5 | لا تعميم جذري |
| OCCURRENCES | query أو structural_query | لا اكتمال دلالي من العد |
| STUDY | الاستعلام المناسب وسجل الدراسة | لا معنى آلي |
| COMPARE | comparison_queries باستعلامين حرفيين | لا ترادف أو اختلاف مفروض |
| HYPOTHESIS | الاستعلام وسجل الفرضيات والنقض | لا قبول تعريف مسبق |
| VERIFY | اقتباس/record/غلاف/تاريخ لأداة الفحص | لا تفسير جديد بدل التدقيق |

التصنيف القاعدي اقتراح ظاهر؛ يفضل mode الصريح الموافق لطلب المستخدم. الغموض المؤثر فقط يحتاج استيضاحًا؛ لا يوجد استنتاج آلي مضمون للجذر من أي سؤال. لا تجمع محددين متعارضين أو ترسل معرف مصدر أو actor. التفاصيل غير الحاسمة توثق بافتراض معلن.
لكل صفحة receipt؛ المتابعة `lisan_prepare_research({question:"متابعة",resume_receipt:...})` تحافظ على المحدد وموضع الصفحة. اجمع الإيصالات والمراجع من النتائج الفعلية قبل check. لا تحدّث next_offset من التخمين.
خريطة الثلاثين اختيار طبقات مؤثرة، لا قائمة محللات منفذة. لا يلزم المرور بكل طبقة. استخدم selected_layers ثم سجل ANALYZED فقط عند وجود ملاحظة وشاهد محلل فعليًا؛ لا تعني العلامة إثبات القراءة بالآلة.
