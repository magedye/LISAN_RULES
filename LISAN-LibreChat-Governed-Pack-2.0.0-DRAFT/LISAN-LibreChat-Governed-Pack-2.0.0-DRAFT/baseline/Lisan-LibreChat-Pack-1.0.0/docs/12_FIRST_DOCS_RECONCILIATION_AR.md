# مراجعة First-Docs ومصالحة المقترحات الجديدة

ظهر هذا المجلد بملفات أضيفت/حُدثت أثناء إعداد الحزمة، فتمت مراجعته وإلحاق نسخه وبصماته قبل الإغلاق. ملفات الدفعة الأولى الخمسة: منهج LISAN ذو 35 بندًا؛ مقترح تجاوز عيوب النماذج الأول؛ تصحيحه الثاني؛ أسباب عدم الالتزام والحلول؛ AGHR_REFERENCE 1.0.0-rc.3. حفظ النسخة لا يعني اعتماد كل ادعاء أو تفعيل تعليمات النشر داخلها.

## قرارات التصحيح

| الفكرة | قرار الحزمة |
|---|---|
| الذاكرة المراجعة أولًا | أضيفت إلى ORCH/COMPARE وroute/cumulative؛ يدويًا ببطاقة فعلية الآن، وآليًا عند تأهيل C03 |
| Blind Lab عند الحاجة | اختياري لطلب استقلال/تشخيص، لا شرط جواب أو حفظ عام؛ ينتج بحثًا ثم يقارنه COMPARE منفصلًا |
| البحث في الجزء غير المغطى | يقارن السؤال بنطاق النتيجة وإصدارها ومراجعتها؛ لا إعادة بحث كاملة بلا سبب |
| فحص خفيف لكل نتيجة | مؤشرات ظاهرة في AUDIT/verify وتعليمات ORCH؛ لا إدخال تفاسير في المدقق الداخلي ولا ادعاء علم بما في التدريب |
| ثمانية مؤشرات انحراف | Dictionary-First، Contextual Leakage، Heritage Bias، Tafsir Contamination، Forced Unification، Generic Overextraction، Letter Semantics Overreliance، Circular Confirmation؛ تستعمل أوصاف فحص لا حالات قبول |
| فحص التوزيع قبل إسقاط المعنى | أضيف منع اشتقاق معنى المفردة من تفسير مسبق للآية؛ يبقى السياق الأصلي شاهدًا مشروعًا |
| حفظ ونسخ واعتماديات | تبقى مركزية عبر السجل اليدوي ثم C02–C04؛ لا أدوات حفظ وهمية في الخادم السباعي |
| مخططات وvalidator وretry محدود | native schema للفحص متاح؛ إلزام المخرجات والمراحل على المضيف فجوة C08، ولا يثبت صحة الدلالة |
| تقليل السياق وFew-shot | القواعد الحرجة في كل Agent، والمهارات المختارة عند الحاجة؛ أمثلة التهيئة بلا نتائج دلالية جاهزة قد تلقّن BLIND |
| تنويع النماذج | خيار تجربة لكل وظيفة؛ ليس شرط استقلال أو ضمانًا لدقة أعلى؛ إعداد temperature تابع لقدرة المزود |
| التقييم والتحديث المحكوم | حالات LC11–LC14 وسجل نسخ وبصمات؛ لا ترقية تلقائية من نجاح الشكل إلى قبول المعنى |

## تعارضات لا ننقلها إلى التنفيذ

1. النص الأول يجعل Lock وBlind Pass شرطًا عامًا، بينما التصحيح الثاني يجعلهما تشخيصًا عند الحاجة. نأخذ اختياريّة التشخيص، ونستخدم تثبيت نسخة قبل المقارنة للتتبع فقط؛ لا Research Lock/Purity ولا حالة canonical جديدة.
2. رموز مثل ACCEPTED وCHALLENGED وNEEDS_REOPEN وPOST_LOCK_EXTERNAL_COMPARISON في الأمثلة ليست حقولًا جديدة نحقنها في عقد المرشح. يبقى research_state وأنواع claims وحالة المراجعة كما يحددها schema الأصلي، وتوثق أوصاف الإجراءات في الدفتر المرافق.
3. بعض المقاطع تستنتج من اتفاق BLIND أصالةَ المنطلق أو من اختلافه تلوثَ الأصل، ثم تقيد ذلك في مقاطع أخرى. المعتمد: الاتفاق والاختلاف لا يثبتان السبب؛ نراجع السؤال والنسخة والتغطية والدليل والبدائل، ونحفظ عدم الحسم. لا نضع سجلًا CLEAR لغياب دليل لم يُبحث.
4. MCP يقدم أدوات وحدودًا لتلك الأدوات؛ وجوده لا يجعله مالكًا لكل سياق LibreChat. العزل الكامل عمل المضيف C01. Subagents الحالي موثق بسياق طفل منفصل، لكن تكليف الأب قد يسرّب النتيجة؛ لذلك لا نساوي سياق الطفل ببحث أعمى مؤهل.
5. الأدوات المقترحة بأسماء open_blind_lab وget_qualified_knowledge وsave_finding وcompute_heritage_signal ليست أدوات الحزمة الفعلية. كتالوجنا المثبت سباعي؛ يعاد استخدام خدمة المستودع الموجودة عند تأهيلها بدل اختلاق توافق API.
6. «أفضل تحليل ممكن عند نقص الأدوات» لا يبرر اختلاق شاهد أو رقم. إن لم يتوفر مصدر ثابت نجيب منهجيًا أو نعرض ما أمكن التحقق منه بنطاقه، دون ملء النقص من الذاكرة.
7. تعليمات تنسيق JSON لا تسبق سلامة المصدر أو سلطة المضيف. لا نعتمد ترتيبًا عامًا يجعل تنسيق المخرج فوق الأمان. لا نخترع ثقة مئوية ولا نطلب سلسلة تفكير خفية.

## ما نأخذه من AGHR

نستفيد من فصل سلطة المنهج، وإرشاد الوكيل، وضبط التنفيذ، وأدلة التحقق؛ ومن أولوية مصدر القاعدة قبل شدتها، وصدق وصف ما اختير/حُمّل/نُفّذ/فُحص، وعدم جعل لغة القاعدة سببًا لتعطيلها، والتأهيل بحسب المضيف والإصدار والنطاق. الحزمة لا تعلن مستوى تبنٍّ L0–L4 ولا تنشئ state.json موازية أو منظومة CI أو خط توليد AGENTS جديدًا. إشارات المضيف غير المرصودة تبقى غير مرصودة. التوقيع والبصمة يثبتان هوية مادة التسليم ضمن حدودهما، لا صلاحية الاستنباط.

تغطية البنود الـ35 في [الخريطة المقابلة](13_LISAN_35_DIRECTIVES_AR.md). هذه البنود تنظيم للوثيقة، وليست إضافة 35 محللًا تلقائيًا إلى الطبقات الثلاثين.
