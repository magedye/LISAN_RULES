# دليل الإعداد والتشغيل

هذا دليل تهيئة، وليس سجل تنفيذ نشر. استعمل مثيل LibreChat مخصصًا لسان، مع قاعدة بيانات ومستخدمين وإعدادات منفصلة عن النسخة الهندسية العاملة في D:/APP/LibreChat. لا تنسخ الإعداد فوق خدمة قائمة دون مقارنة حاجاتها. الحزمة لا تثبت LibreChat نفسه أو MongoDB أو مزود نموذج.

## المتطلبات

- نسخة تدعم Agents وSkills وSubagents وMCP. مرجع الحزمة هو commit المثبت في SOURCES_AR؛ لا تستخدم كلمة latest بدل تسجيل الإصدار. الاعتماد على v0.8.8 المحلية يظل مقيدًا بما أثبته تقرير التوافق؛ لا ترقية تلقائية.
- Node 22 أو أحدث يمكن لحساب خدمة LibreChat تشغيله. المسار المقترح Windows هو C:/Program Files/nodejs/node.exe. نُفذ الفحص المحلي بـNode v24.11.0.
- مزود/نموذج عامل يدعم الأدوات. اختره من Agent Builder بعد اختباره؛ مفاتيحه تبقى في بيئة المثيل. لا توجد مفاتيح في الحزمة. تطبيق أدوات البحث محلي، أما استخدام نموذج سحابي فينقل إليه مدخلات ومخرجات البحث بحسب إعداد مزودك.
- حساب إعداد مخول بإنشاء Agents وإدارة Roles؛ ثم حساب باحث عادي لا يغير الإعداد المنهجي أثناء التجربة.

## Windows Native

1. أبق المجلد في موضعه الحالي. في بيئة **المثيل المخصص** أضف سطري [native.env.example](../config/native.env.example). لا تستبدل ملف .env كاملًا بهما.
2. راجع مسار node ومسار runtime في [librechat.native.yaml](../config/librechat.native.yaml). المساران حقيقيان في هذا الجهاز، ولا توجد placeholders في الملف الأساسي. إذا نقلت الحزمة عدّلهما إلى الموضع الجديد.
3. أعد تشغيل المثيل المخصص بالطريقة المعتمدة لنشره لتحميل YAML والمهارات. هذه الخطوة ينفذها المشغّل لاحقًا؛ لم تنفذ أثناء إعداد الحزمة.
4. افحص سجلات البدء: تحميل الإعداد، 19 مهارة، وخادم lisan_readonly. عدم ظهور مهارة أو MCP مشكلة تهيئة، ولا يعالجها النموذج بالادعاء أن الأداة نفذت.
5. أنشئ COLLECT وMORPH وSEM وCRITIC وAUDIT أولًا من أوراق agents، ثم ORCH واختر الأطفال الخمسة من القائمة، ثم BLIND. الأسماء رموز بشرية؛ لا تضعها مكان Agent IDs في طلبات API. COMPARE/SCIENCE/HISTORY اختيارية.
6. راجع Tools لكل وكيل: الأدوات السبع فقط. Skills = Selected لا All؛ authoring = Off. لا ملفات معرفة على الوكلاء الداخليين. لا self-spawn ولا مشاركة ملفات للأطفال.
7. بعد الإنشاء استعمل [librechat.trial-locked.yaml](../config/librechat.trial-locked.yaml) بدل native في CONFIG_PATH لتقليل الإنشاء/تغيير النموذج للباحثين، وراجع Roles وملكية الوكلاء والمشاركة الخاصة. لا يمنع هذا Admin أو المالك من التعديل، ولا يعادل إنفاذ مصدر شاملًا.
8. في دردشة جديدة للوكيل نفذ طلب «افحص الجاهزية والأدوات الفعلية واشرح حدودها دون تحليل دلالي». يجب أن تظهر أداة lisan_status الفعلية. نجاح سكربت هذه الحزمة لا يغني عن هذا الفحص داخل LibreChat.
9. نفذ مصفوفة القبول، وسجل نسخة LibreChat والنموذج والمزود وتعليمات الوكيل ونتائج الأدوات. لا تستخدم في الاختبار بيانات حساسة أو مصادر مُدخلة بلا تصنيف.

## الحاويات

[librechat.container.yaml](../config/librechat.container.yaml) يستخدم `node` و`/opt/lisan/runtime/tools/stdio.mjs`. ملف [compose.lisan.override.yaml](../config/compose.lisan.override.yaml) يربط الحزمة للقراءة فقط ويضبط CONFIG_PATH وDEPLOYMENT_SKILLS_DIR لخدمة اسمها api. طبّقه مع ملف Compose الخاص **بمثيلك المخصص** بعد التحقق من اسم الخدمة وإصدار Node داخل صورته. ليس ملف Compose مستقلًا، ولم يُشغّل أو يُؤهل Docker في هذه المهمة. متغيرات البيئة وباقي التخزين والاتصالات ملك إعداد ذلك المثيل.

## المكتبة والمشاريع

أضف نصوص prompts إلى مكتبة Prompts يدويًا، باسم كل ملف ووصفه. النص بين المعقوفين مدخل يملؤه الباحث، وليس متغيرًا نستند إلى دعم تلقائي لاستبداله. إذا أردت Preset لاحقًا، أنشئه من واجهة نسختك واحفظ منه إعداد العرض/النموذج الفعلي؛ لا تستورد schema غير مثبتة. الأساس يستخدم Agents، لذلك Presets معطلة لتجنب ازدواج تعليمات النظام.

أنشئ مشروع «لسان — أبحاث داخلية» وانسخ تعليمات projects/RESEARCH.instructions.md. لا ترفع sources/ أو الدراسات السابقة أو كتب التفسير إليه. المشروع ينظم المحادثات والتعليمات، ولا يثبت نموذجًا ولا يضمن عزل ذاكرة. BLIND يُفتح خارج جميع Projects، ومن New chat لا من Fork للمحادثة الحالية.

## المسارات الخارجية

COMPARE يستطيع مقارنة نصوص مصادر أدخلها المشغّل عمدًا بعد تثبيت نسخة البحث. SCIENCE وHISTORY يستطيعان تقويم المصادر المقدمة مع التصريح بما تحقق من الوصول إليه. لا توجد في إعداد الحزمة أدوات تصفح خارجية. الحاجة إلى بحث حي تُلبّى في مثيل خارجي منفصل بعد تهيئة Web Search ومزوده من وثائق LibreChat، أو ربط MCP مصادَق عليه خاص بالبحث. اختر تلك الأدوات فقط لهؤلاء الوكلاء هناك، ثم نفذ اختبارات الفصل قبل الاستعمال؛ لا تفعّلها على المثيل الداخلي صامتًا.

لتنفيذ خيار بحث حي بلا برمجة، يوجد [librechat.external.yaml](../config/librechat.external.yaml) مع [external.env.example](../config/external.env.example). استعملهما في المثيل الخارجي وحده، وضع مفتاح Tavily الحقيقي في بيئته؛ يضبط الملف البحث وجلب الصفحات بالمزود نفسه ويعطل reranking، ثم اختر Web Search لوكلاء COMPARE/SCIENCE/HISTORY فقط. يبقى File Search وMemory معطلين. الملف يطلب مراجعة أداة الويب وفق toolApproval؛ لا تغيره إلى bypass لحل خطأ إعداد. لم يُستدع مزود البحث أو يُختبر هذا الاتصال؛ الدليل المتاح تحقق schema فقط. [إعداد Web Search الرسمي](https://www.librechat.ai/docs/configuration/librechat_yaml/object_structure/web_search).

تفعيل File Search يتطلب خدمة RAG مهيأة بالفعل. ارفق في المسار الخارجي المصادر التي صُنفت فقط؛ سجل الكتاب/المؤلف/الإصدار/الصفحة والرابط. درجة الصلة وترتيب النتائج ليستا درجة ثقة بالقول، وغياب نتيجة RAG ليس نفيًا للورود.

## Agent Plugins

الحزمة تستعمل DEPLOYMENT_SKILLS_DIR وmcpServers مباشرة. هذا كافٍ دون نقل ملفات ChatGPT `.codex-plugin` أو `.app.json` إلى LibreChat. نظام Agent Plugins الحالي تجريبي وله plugin.json وmcp.json بعقود مختلفة. لا توجد فائدة منه تبرر اعتماد مسار إضافي هنا؛ إن اختير لاحقًا فليكن إعادة تعبئة للملفات نفسها مع اختبار تحمّل الأخطاء، لا كتابة محرك جديد أو تفعيل hooks بلا حاجة. [المصدر الرسمي](https://www.librechat.ai/docs/features/agent_plugins).

## التراجع والتوقف

احفظ إعداد المثيل المخصص قبل التغيير. عند فشل التهيئة أعد CONFIG_PATH وDEPLOYMENT_SKILLS_DIR إلى قيمهما المسجلة، ثم أعد تشغيل ذلك المثيل فقط. احتفظ بالمحادثات والسجلات، ولا تحذف قاعدة بيانات أو تعيد نسخة احتياطية تلقائيًا. إذا فشلت أداة المتن أثناء البحث فبلّغ عن نقص المصدر ولا تولد بديلًا من الذاكرة.
